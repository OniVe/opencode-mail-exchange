# Почтовый плагин OpenCode V2 для Exchange: что можно взять готового

**Дата среза:** 23 октября 2026.
**Стек-цель:** Bun + TypeScript + Biome, без сборки (`dist`), плагин OpenCode V2.
**Проверено:** документация OpenCode V2, npm registry, GitHub, Microsoft Learn/Exchange Team Blog.
**Живая проверка:** EWS + NTLM из Bun на `<ews-host>` — см. `docs/spike-ews-2026-10-23.md`.

---

## 1. Краткий ответ

1. **Стек реализуем как задумано.** Плагин OpenCode V2 грузится из `.ts` напрямую (Bun), `dist` не нужен — официально поддерживается `exports: "./src/index.ts"`. Biome и `bun test` с этим сочетаются. Готового почтового плагина для OpenCode/Claude Code **нет**, как и TS/JS EWS-MCP.
2. **Протокол зависит от того, где ящик:**
   - **Exchange on-prem (SE):** EWS — единственный API с полным покрытием (почта, папки, флаги, календарь, контакты). JS-библиотека ровно одна: `ews-javascript-api` (MIT, 0.15.3, 2024-05) — полу-поддержка, CJS, без channel binding.
   - **Exchange Online:** EWS с 01.10.2026 блокируется по умолчанию, с 01.04.2027 отключается навсегда. Остаётся **Microsoft Graph** (или IMAP/SMTP с OAuth как урезанный fallback).
   - **Гибрид:** два бэкенда за общим интерфейсом, выбор по расположению ящика.
3. **Переиспользовать:** `imapflow`/`nodemailer`/`mailparser` (IMAP-путь, живы, Bun протестирован), `@azure/msal-node` + `fetch` (Graph), `ews-javascript-api` + `@ewsjs/*` (EWS on-prem). Каталоги tool-схем — из MIT-проектов `viartemev/outlook-ews-mcp` (57 tools) и `azizmazrou/ews-mcp` (28 tools, safety-модель).
4. **Писать самим:** сам плагин (tool-слой, auth через `ctx.integration`, safety-политика), autodiscover для on-prem, alias-id/кэш, NTLM там, где библиотека его не умеет (IMAP/SMTP).

## 2. OpenCode V2: подтверждение стека

**Версии на 2026-10-23:** CLI `@opencode/cli` 2.1.3, SDK `@opencode/plugin` 2.1.3; на машине установлен CLI **2.0.26** → SDK пинить на `2.0.26` (версии ходят парами; `^` подтянет 2.1.x).

### 2.1. Загрузка и «без dist»

| Факт | Подтверждение |
|---|---|
| Автозагрузка `.opencode/plugins/*.ts` и каталогов-пакетов | docs «Discover» |
| Глобальные плагины: `~/.config/opencode/plugins/` | docs «Discover» |
| Публикация без сборки: `exports: { ".": "./src/index.ts" }` | docs «Publish» |
| TS исполняет Bun в процессе сервера, типы стрипаются | исходники `plugin/src/source.bun.ts`, `runtime/import.bun.ts` |
| `@opencode/plugin` и `effect` подменяются host-копиями | `plugin/src/runtime.ts` |
| Зависимости пакетного плагина ставит OpenCode (arborist, кэш `~/.cache/opencode/npm/...`) | `util/src/npm.ts` |
| Зависимости **локального** плагина OpenCode не ставит — нужен свой `bun install` | исходники `load()` |
| Hot reload: файлы плагина и конфиг вотчатся; `opencode reload`; изменения в `node_modules` — только `opencode service restart` | docs «Reload» |

Рабочий локальный референс ровно в этом стеке: `C:\project\ai\opencode-orchestrator-uni` — `exports → ./index.ts`, Biome 2.5.x, `bun test`, `@opencode/plugin ^2.0.28`, комментарий в шапке: «no build step and no dist».

### 2.2. Что важно для почтового плагина

- **API:** `Plugin.define({ id, setup(ctx) })` из `@opencode/plugin`.
- **Tools:** `ctx.tool.transform(editor => editor.add({ name, description, input, execute }))`. Схема — JSON Schema (или Standard Schema: Zod/Valibot/ArkType); Zod не обязателен.
- **КРИТИЧНО:** по умолчанию `codemode !== false`, т.е. инструмент доступен модели только через Code Mode tool `execute`. Для прямых вызовов `mail_*` нужно `options: { codemode: false }`.
- **Трансформы синхронные и replayable:** данные грузить до callback, затем `domain.reload()`.
- **Секреты:** отдельного `auth`-хука в V2 нет. Замена — `ctx.integration`:
  - методы `key`, `oauth`, `command`, `external`, `env`;
  - `ctx.integration.oauth.connect/status/complete/cancel`, `connect.key`, `command.connect`;
  - `connection.active(id)` → `connection.resolve(conn)` → `{type:"key"|"oauth"|"external", ...}`.
- **Состояние:** `ctx.storage` — durable JSON, scoped по id плагина; шифрование не документировано → токены туда не класть.
- **Права:** `ctx.permission.assert({ action, resources })` — удобно для «отправка письма требует подтверждения».
- **События:** `ctx.event.subscribe({ signal })`.
- **Песочницы нет:** плагин исполняется in-process с правами пользователя (fetch, fs, child_process доступны).
- **Идентификатор:** дубликат `id` — fatal; id стабилен (диагностика, storage, enable/disable).
- **Логи:** `console.log` → `~/.local/share/opencode/log/opencode.log` (`role=server`).
- **V1-плагины в V2 не работают:** другой пакет, другой entrypoint, другой API хуков.

### 2.3. Скелет

```ts
// .opencode/plugins/mail/index.ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "acme.mail",
  async setup(ctx) {
    await ctx.tool.transform((tools) => {
      tools.namespace({ name: "mail", description: "Exchange mailbox" })
      tools.add({
        name: "search",
        description: "Search messages in the mailbox",
        input: {
          type: "object",
          properties: {
            query: { type: "string", maxLength: 512 },
            limit: { type: "integer", minimum: 1, maximum: 50 },
          },
          required: ["query"],
          additionalProperties: false,
        },
        options: { namespace: "mail", codemode: false, permission: "mail.search" },
        execute: async (input, context) => {
          const { query, limit = 10 } = input as { query: string; limit?: number }
          const backend = await getBackend(ctx)
          return { content: await backend.search(query, limit, context.signal) }
        },
      })
    })
  },
})
```

## 3. Exchange: варианты доступа на 23.10.2026

### 3.1. Статус EWS

| Дата | Событие |
|---|---|
| 19.09.2023 | Анонс retirement EWS в Exchange Online; on-prem не затрагивается |
| 05.02.2026 | План: `EWSEnabled`, AppID Allow List, поэтапное отключение |
| **01.10.2026** | Тенанты без opt-in получают `EWSEnabled=False` — EWS заблокирован (админ может временно вернуть) |
| 21.10.2026 | Microsoft: «retirement is now in progress» |
| **01.04.2027** | Полное отключение, `EWSEnabled` удаляется |

Следствие: для Exchange Online EWS — **не вариант**. Для on-prem EWS остаётся полностью поддерживаемым.

### 3.3. Аутентификация

- **On-prem:** **NTLMv2 проверен на живой среде** (см. spike): `@ewsjs/ntlm-client` 3.0.1 через `@ewsjs/xhr` работает из Bun 1.4.2. Basic на проверенном сервере **отключён** (401), хотя политика его «разрешает» — полагаться на Basic нельзя. `fetch`/undici NTLM не умеют.
- **Внутренний CA:** Bun не использует хранилище сертификатов Windows. Если EWS за внутренним CA, обязателен `NODE_EXTRA_CA_CERTS` с PEM корневого CA (проверено) или опция `ca`; `rejectUnauthorized: false` — только для отладки.
- **EPA (Extended Protection):** с Exchange 2019 CU14 включена по умолчанию; FE EWS — `Allow` (NTLM без CBT проходит), BE EWS — `Required`. Если админ выставил `Required` на FE — **ни одна известная JS-библиотека не пройдёт** (CBT не поддерживается). Обход: Basic, либо sidecar на `node-libcurl`, либо отдельный процесс с нативным NTLM.
- **EXO:** Basic отключён с 2022. Graph — app-only (`ConfidentialClientApplication` + RBAC for Applications) или delegated device code (`acquireTokenByDeviceCode`, включить public client flows). IMAP/SMTP — OAuth2 (`IMAP.AccessAsUser.All`/`SMTP.Send` или app-only `IMAP.AccessAsApp`/`SMTP.SendAsApp` + service principal).

### 3.4. Lifecycle on-prem

- Exchange 2016/2019 — extended support закончился **14.10.2025**.
- **Exchange Server SE** — в поддержке с 01.07.2025, актуальная ветка (RTM 15.2.2562.17, May 2026 HU — 15.2.2562.41).
- `ews-javascript-api` официально заявляет Exchange 2007–2016; совместимость с 2019/SE предполагается по обратной совместимости EWS, но не документирована — проверять на стенде.

## 5. Рекомендуемая архитектура плагина

```
src/
  index.ts              Plugin.define + setup
  config.ts             ctx.options + env, валидация
  backend/types.ts      MailBackend (общий интерфейс)
  backend/ews.ts        EWS on-prem (ews-javascript-api + @ewsjs/xhr)
  backend/graph.ts      EXO (fetch + msal; graph-client опционально)
  backend/imap.ts       fallback/почта без календаря
  auth/integration.ts   ctx.integration: key / oauth device code / command
  tools/                схемы и executors
  safety.ts             permission.assert, лимиты, draft-first
```

Интерфейс (по отчёту по протоколам):

```ts
interface MailBackend {
  listFolders(): Promise<Folder[]>
  listMessages(q: Query): Promise<Message[]>
  getMessage(id: string): Promise<Message>
  send(msg: Outgoing): Promise<void>
  setFlags(id: string, flags: Flags): Promise<void>
}
```

**Набор tools (минимум, по образцу viartemev/azizmazrou):**

| Tool | Назначение | Особенности |
|---|---|---|
| `mail_folders` | список папок | read-only |
| `mail_list` | список писем (метаданные) | лимит, пагинация, без тела |
| `mail_search` | поиск | `maxLength` на query, лимит результатов |
| `mail_get` | письмо + тело | обрезка тела, HTML→text |
| `mail_thread` | цепочка | через `ConversationId`/`References` |
| `mail_draft` | создать черновик | **по умолчанию** вместо отправки |
| `mail_send` | отправить | `ctx.permission.assert` + подтверждение |
| `mail_reply` / `mail_forward` | ответ/пересылка | draft-first |
| `mail_move` / `mail_flags` | папки/флаги | идемпотентность |
| `mail_attachment_get` / `_add` | вложения | лимит размера, MIME-whitelist |

Все — `options: { namespace: "mail", codemode: <опция плагина>, permission: "mail.<tool>" }` (по умолчанию `false`).

**Auth:** `ctx.integration` с методами `key` (Basic/NTLM-учётка) и `oauth` (device code для Graph); `connection.resolve()` на каждый вызов, кэш токена — в памяти + `ctx.storage` только для non-secret (`deltaLink`, alias-map). Секреты — интеграции/`process.env`, не storage.

**Маршрутизация:** домен ящика из конфига; on-prem → EWS, cloud → Graph; ошибка `MailboxNotEnabledForRESTAPI` → fallback/явная ошибка. Graph для on-prem не пытаться использовать.

**Безопасность:** read-only по умолчанию, draft-first, подтверждение отправки, лимиты тела/вложений, редакция секретов в логах, один `ExchangeService`/`XhrApi` на ящик (внутреннее состояние мутабельно).

## 6. Spike: выполнен 23.10.2026

Spike проведён на живом сервере (`<ews-host>`, Exchange 2016) — детали и воспроизведение: `docs/spike-ews-2026-10-23.md`. Итоги:

1. **Чтение:** `FindFolders` (18 папок), `FindItems(Inbox)` + темы/даты, `FindAppointments`, `FindItems(Contacts)` — работают из Bun.
2. **Запись:** черновик с вложением (`Save` + `Attachments.AddFileAttachment`), чтение обратно, `HardDelete` — работают.
3. **Отправка:** `EmailMessage.Send()` — 478 мс; доставка в Inbox ~5 с; тестовое письмо удалено.
4. **Тело письма:** загружается только с явным `EmailMessageSchema.Body` в `PropertySet` (иначе `bodyLength=0`).
5. **TLS:** без `NODE_EXTRA_CA_CERTS` запрос к внутреннему CA падает; фактический симптом в стеке —
   `Exception: undefined is not an object (evaluating 'response.headers')` из `@ewsjs/xhr` (`ntlmProvider.preCall`),
   а не `UNABLE_TO_VERIFY_LEAF_SIGNATURE` (см. `spike-ews-2026-10-23.md` §3).
6. **Auth:** Basic отключён на сервере, рабочий путь — NTLMv2.

Осталось проверить перед реализацией: несколько ящиков/делегирование, большие вложения, HTML с inline-картинками, холодный старт `ews-javascript-api`, EPA-режим FE EWS.

## 7. Риски и открытые вопросы

| Риск | Влияние | Митигация |
|---|---|---|
| `ews-javascript-api` полу-мёртв (релиз 2024, CJS, 73 issues) | среднее | пин версии, патч #459, изоляция в адаптере, тесты на стенде |
| NTLM в Bun (`agent-base`/cookie-agent) | **снят** | проверено 23.10.2026: чтение, черновик с вложением, отправка (см. spike) |
| Basic отключён на сервере, хотя политика «разрешает» | высокое | конфиг плагина только NTLM; Basic не считать доступным |
| EWS за внутренним CA, Bun не видит системный store | **высокое** | `NODE_EXTRA_CA_CERTS`/`ca` с PEM корневого CA; проверено |
| EPA `Required` на FE EWS → CBT | **высокое** | на проверенном сервере не `Required` (NTLM прошёл); уточнять для других серверов |
| EWS retirement в EXO (01.10.2026 / 01.04.2027) | высокое для cloud | Graph как основной бэкенд для EXO |
| Exchange 2016/2019 вне поддержки | среднее | целевая среда — Exchange SE |
| Graph on-prem не поддерживается с 07.2023 | высокое для гибрида | маршрутизация по расположению ящика |
| `codemode` по умолчанию true | tool не виден модели | опция плагина `codemode` (default `false` для прямых вызовов) |
| SDK/CLI версии расходятся (2.1.3 vs 2.0.26) | низкое | пин `@opencode/plugin@2.0.26` |
| Локальный плагин не получает зависимости автоматически | низкое | `bun install` в каталоге плагина |

**Входные данные (подтверждено владельцем и spike):**
1. Ящики — **on-prem Exchange** (`<ews-host>`, Exchange 2016 build 15.1.2507.6).
2. Basic заявлен как разрешённый, но на сервере **фактически отключён**; рабочий путь — NTLMv2.
3. Нужны почта **и календарь/контакты** → EWS, не IMAP.
4. Отправка из плагина нужна (проверена).

**Открытые вопросы:**
- Планы по Exchange 2016 (вне поддержки с 14.10.2025) — остаётся или миграция на SE/Online (влияет на второй бэкенд)?
- Один ящик или несколько/делегирование?
- Нужен ли доступ к общим ящикам (shared mailbox) и папкам других пользователей?

## 8. Реализация v0.1 (23.10.2026)

Каркас плагина готов и проверен на живом сервере (read-only smoke): `src/index.ts`, `src/backend.ts`,
`src/store.ts`, `src/tools.ts`, `src/config.ts`. Подробности — `README.md`.

- **Стек:** Bun 1.4.2, TS strict, Biome 2.5.15, `exports: "./src/index.ts"` (без dist), `@opencode/plugin@2.0.26`.
- **Backend:** EWS + NTLM, один `ExchangeService` на аккаунт (внутреннее состояние библиотеки мутабельно), `SyncFolderItems` для инкрементального индекса.
- **Store:** `bun:sqlite` (WAL, FTS5), режимы `off`/`metadata`/`full`, тела лениво.
- **Tools:** `mail_folders/list/search/get/sync/draft/send/calendar/contacts`; `codemode` — опция плагина (default `false`).
- **Проверки:** `bun run typecheck`, `bun test` (28 тестов на момент среза; после round 2 — 51), `bun run lint` — чисто; live smoke: папки 18, inbox 3,
  тело 23 810 символов, FTS-поиск, календарь 0, контакты 0.
- **Нюансы, найденные при реализации:** `SyncFolderItems` не принимает `Body`/`ToRecipients` в property set;
  `LoadPropertiesForItems` падает на пустой коллекции (в `list/search` вызывается только при `Items.length > 0`);
  `UnreadCount`/`TotalCount` нужно явно просить в `FolderView`.
- **Permission:** в `@opencode/plugin@2.0.26` нет `ctx.permission.assert` (появился позже) — используется
  `options.permission` на инструменте (`mail.read`/`mail.draft`/`mail.send`).
- **Несколько ящиков:** `MailService` + `AsyncLocalStorage`-роутер `XhrApi`; конфиг `accounts[]`, у каждого свой
  `ExchangeService`, SQLite (`dataDir/<id>`, каталог на аккаунт всегда, id валидируется) и credentials. Проверено: valid → 200, invalid → 401, без контекста → ошибка.
- **Таймауты:** `requestTimeoutMs` передаётся в `XhrApi({ timeout })` через ALS-контекст; проверено: 1 мс → запрос падает, 20 с → 18 папок.
- **HTML-тело:** библиотека не экранирует текст в SOAP — плагин делает `escapeXml` для subject/body; иначе HTML
  сохраняется пустым без ошибки. Inline `cid:`-картинки проверены на draft/send/receive.
- **Вложения:** 5/10/20/30/40 МБ — OK (до 20.7 с, RSS до 245 МБ, рост памяти 3.5–4.2× от размера файла); 50 МБ — HTTP 413.
  Локальные лимиты плагина (введены после замера): 40 МБ decoded на вложение и 10 вложений на письмо, проверяются
  до EWS; HTTP 413 остаётся только для обхода/отключения локальной проверки.
- **Холодный старт:** ~730 мс (import 285 + первый вызов 445), RSS 86 МБ. `lab/perf-cold.ts` печатает `folders: 5` —
  артефакт `FolderView(5)` в самом скрипте, а не число папок (реально 18).

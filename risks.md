# Принятые риски

## M7 (закрыт 2026-10-23)

Отмена in-flight EWS-запроса реализована: `context.signal` из tool-execute → `MailService.run` → `AsyncLocalStorage` → axios-интерцептор (`src/xhr-router.ts`); отмена возвращает `EWS request cancelled`. Покрыто тестом `xhr-router` (abort висящего запроса) и `service` (маппинг `ERR_CANCELED`). Ограничение `requestTimeoutMs` остаётся верхней границей.

## Прочие риски

- Локальный индекс — plaintext SQLite; защита — ACL/BitLocker, не шифрование плагина.
- `ews-javascript-api` полу-поддерживается (последний релиз — 0.15.3, 2024-05-13); обновления проверять отдельно.
- Для отмены запросов плагин процесс-глобально патчит CJS-инстанс axios (`createRequire` + `axios.create`); вне ALS-контекста интерцептор no-op, но патч не снимается при выгрузке. При отсутствии `node_modules` отмена отключается с warning, таймаут остаётся.
- EWS в Exchange Online выключается (01.10.2026 блокировка, 01.04.2027 shutdown); для EXO нужен Graph-бэкенд (не реализован).
- `uuid` (transitive): `ews-javascript-api@0.15.3` → `uuid@9.0.1` (used as v4 without `buf`) и `@azure/msal-node@2.16.3` → `uuid@8.3.2`; обе версии формально уязвимы к GHSA-w5hq-g745-h8pq (moderate, v3/v5/v6 with `buf`), но уязвимый API в плагине не задействован. Исправление — uuid 11.1.1, вне диапазонов зависимостей. Пересмотреть вместе с R4 (форк/вендоринг `ews-javascript-api`).
- `caFile` расширяет **process-global** TLS trust store через `tls.setDefaultCACertificates`; изменение не откатывается при выгрузке плагина. Непустые встроенные корни сохраняются; отсутствующий путь — `ConfigError`, существующий нечитаемый/невалидный файл пропускается и логируется по аккаунту, остальные валидные файлы применяются. Хэш содержимого переприменяет PEM, заменённый по тому же пути, но старый корень не отзывается — он остаётся доверенным до перезапуска процесса.
- `mail_delete` с `hard: true` и `mail_empty_deleted` необратимы: EWS удаляет письма окончательно. Оба режима `mail_delete` tombstone'ят локальные строки; при soft-удалении Exchange выдаёт новый ItemId, поэтому старый id становится недействительным до sync/перечитывания `deleted`. Empty удаляет только элементы верхнего уровня, подпапки остаются. Успехом считается только `ServiceResult.Success` по каждому элементу; `Warning` и пустой `Responses` не подтверждают удаление. При полной ошибке EWS индекс не меняется; при частичной — применяются только подтверждённые удаления, вызов падает со счётчиками. Транспортная ошибка после запроса оставляет исход неизвестным — перед повтором нужен `mail_sync`.
- Гонка delete/empty с in-flight `SyncFolderItems`: синхронизация, снявшая снимок до удаления, может применить `upsertMessages` после tombstone и временно вернуть строку; состояние исправляет следующий `mail_list`/`mail_sync` по этой папке, а `mail_search` sync не запускает.
